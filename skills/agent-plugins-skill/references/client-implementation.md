# 客户端加载器与一致性验证

来源：[正式规范 §4–11](https://agent-plugins.org/specification)、[客户端入门](https://agent-plugins.org/client-implementers/implement-an-agent-plugins-client)、[加载与发现](https://agent-plugins.org/client-implementers/loading-and-discovery)、[MCP 运行](https://agent-plugins.org/client-implementers/mcp-runtime)、[一致性清单](https://agent-plugins.org/client-implementers/conformance)。官网清单是非规范性便利材料，冲突时以正式规范正文为准。

## 范围与最小实现

合规客户端能从目录路径加载插件，先校验根 `plugin.json`，且至少支持 **技能或 MCP** 中的一类。仅支持技能的客户端也可合规；若支持 MCP，至少支持 `stdio` 与 `streamable-http` 之一，建议两者都支持，旧 `sse` 可选。客户端可以忽略未实现的组件类型和扩展命名空间，不应把“未支持”本身当作插件错误。

安装源、仓库/市场、启停与更新 UX、权限提示、信任政策、沙箱、技能如何显示或注入模型、各扩展命名空间内部逻辑，均是客户端自己的设计，不由 Agent Plugins 1.0.0 规定。不要在一致性声明中暗示规范保证这些能力。规范的包路径包含检查也不提供进程沙箱。

## 加载顺序

1. 从输入目录确定真实插件根，拒绝访问真实路径逃出根的包文件。检查根 `plugin.json` 真实路径被包含。
2. 读取根 manifest，用 `$schema` 选择**本地已有**的规范规则；不在加载中抓取远端 Schema。缺失、不支持的版本或其他致命字段错误拒绝整包。未知顶层字段要报告并忽略；非对象 `extensions` 要报告并忽略；其他合法字段继续使用。
3. 只对本客户端支持的组件类型，从固定路径发现：`skills/` 的即时子目录；根 `mcp.json`。缺失路径正常；错误文件种类/路径逃逸仅禁用该组件类型。
4. 逐项校验技能和 MCP 服务，按最窄边界跳过坏项。实际启动/连接某 MCP 服务失败时继续其他组件。
5. 只处理自己实现的反向域名扩展；文件型扩展只查看与该命名空间同名的顶层目录。未知扩展内容不验证。
6. 输出分层诊断：整包拒绝、组件类型失效、条目跳过、运行连接失败、仅不受支持。保留有效组件的加载结果。

## 故障边界速查

| 情况 | 预期处理 |
| --- | --- |
| `plugin.json` 缺失、无效、不支持的 `$schema` 或真实路径逃逸 | 拒绝整个插件，不发现/执行组件。 |
| manifest 有未知顶层字段 | 报告并忽略字段；若其他字段有效继续。 |
| `extensions` 不是对象 | 报告并忽略此字段；继续。 |
| 未实现扩展命名空间 | 不检查值内容，直接忽略。 |
| `skills/`、`mcp.json` 缺失 | 正常缺省。 |
| 固定位置种类错误或真实路径逃逸 | 禁用对应组件类型；其他类型继续。 |
| 单个 `SKILL.md` 无效或越界 | 跳过该技能；兄弟技能继续。 |
| `mcp.json` 顶层 JSON、Schema、字段或版本无效 | 禁用 MCP 类型；技能继续。 |
| 单个 MCP 条目无效或传输未支持 | 跳过该服务；其他服务/技能继续。 |
| 单个 MCP 服务启动、连接、认证或握手失败 | 报告连接故障并继续其他服务/技能。 |
| 其他包文件的真实路径逃逸 | 拒绝访问该路径。 |

## MCP 运行实现要点

在确认 `mcp.json` 顶层有效后，单独验证每个服务的闭合类型。初次连接严格按条目 `type`。stdio 的 `command` 是单 token，`args` 分别传递；默认 `cwd` 是插件根；先建立持久可写 `PLUGIN_DATA`，然后按顺序合成环境变量：基础环境 → 配置 `env` → 客户端保留变量。只在指定字段做单次、非递归的 `${PLUGIN_ROOT}` / `${PLUGIN_DATA}` 展开。远程连接必须检查 URL/headers，不把配置头未经授权带到不同 origin。授权逻辑遵循 MCP，不能用自造的可移植密钥字段代替。详细字段规则见 [mcp-servers.md](mcp-servers.md)。

## 可执行的一致性测试矩阵

用临时目录组装真实包，断言**加载结果与诊断**，不要只断言解析函数返回值。每个案例中加入另一个有效技能/服务，观察它是否继续加载。

| ID | 输入变体 | 预期可观察结果 |
| --- | --- | --- |
| M1 | 最小合法 manifest、无组件目录 | 包可加载；组件为空。客户端自身仍须具备至少一类支持能力。 |
| M2 | `name` 为 `A`、`a..b`、`a--b`，或缺 `$schema` | 整包拒绝，组件未执行。 |
| M3 | manifest 加未知顶层字段 | 报告该字段，其他有效组件加载。 |
| M4 | `extensions: []` 与未知扩展键的任意值 | 前者报告并忽略；后者不验证值而继续。 |
| P1 | `plugin.json` 符号链接到根外 | 整包拒绝。 |
| P2 | `skills/` 为普通文件；`mcp.json` 合法 | 技能类型失效，MCP 可继续。 |
| S1 | 两个即时子技能，一个坏 frontmatter | 只跳过坏技能；不递归加载深层技能。 |
| S2 | 单个 `SKILL.md` 符号链接到根外 | 只跳过该技能。 |
| C1 | `mcp.json` 有额外顶层字段或与 manifest 版本不匹配 | 只禁用 MCP 类型，技能仍加载。 |
| C2 | 两个 MCP 条目，一个缺必需字段/混入其他类型字段 | 只跳过坏条目。 |
| C3 | stdio `command` 含空格的 shell 字符串或 `../`；`cwd` 越界 | 相应服务无效，不启动。 |
| C4 | `env` 定义保留变量，或把 `${PLUGIN_ROOT}` 放在 `command` | 前者条目无效；后者命令不展开，按命令规则处理。 |
| C5 | HTTP 非 loopback URL 使用 `http`、有 fragment、或重复大小写不同的头名 | 相应条目无效。 |
| R1 | MCP 进程失败、HTTP 授权失败、握手失败 | 标记该服务连接失败，其余服务/技能继续。 |
| R2 | 插件更新后再次启动 | `PLUGIN_DATA` 仍有先前数据，`PLUGIN_ROOT` 指向当前包。 |
| R3 | 远程重定向至不同 origin | 未获用户明确授权时不转发配置 headers。 |

JSON Schema 能帮助检查形状，但 M3/M4 的规范性非致命处理、真实路径、URL 语义、环境展开与运行隔离，需要额外的客户端逻辑和测试。明确声明测试覆盖的组件与传输；未实际运行的传输标为未验证。
